# 판매자 제공 실제 상품 등록: 동의 항목·CSV/JSON 양식

현재 제공하는 양식에는 **상품 행이 없습니다**. 시험 상품·가짜 10개를 실제 등록 상품으로 넣지 않습니다. 운영 DB·Firebase·회원·구독과 연결하지 않는 로컬 파일 검증/공개 스냅샷 방식입니다.

- CSV: [`templates/seller-products.csv`](../templates/seller-products.csv) — 헤더만 있는 양식
- JSON: [`templates/seller-products.json`](../templates/seller-products.json) — `version:1`, 빈 `products` 배열
- 검증/가져오기: `node scripts/import-product-catalog.cjs`
- 기본 공개 스냅샷: `assets/approved-products.json`
- 별도 운영자 검토 목록: `catalog/source-approvals.json` (공개 빌드에 포함하지 않음)

## 판매자에게 받아야 할 실제 동의와 자료

운영자는 적어도 다음을 확인하고 보관해야 합니다. 자동으로 동의를 얻거나 계정을 만들지 않습니다.

1. 판매자/브랜드의 신원과 상품 정보를 제공·이용 허락할 권한, 실제 현재 판매 중인 상품이라는 확인.
2. A1 FASHION 무료 베타에서 상품명·브랜드·가격/통화·색상·사이즈/실측표·판매처·구매 링크를 공개하고 검색/비교/규칙 추천에 사용하는 범위.
3. **상품 이미지 표시권**과 허용 이미지 호스트. 타사 촬영물·모델 초상·상표 이용권 포함 여부. 단순 표시와 이미지 저장/리사이즈·2D 배치·AI 합성·3D 복원은 별도 권리이며 현재 등록은 표시권만 승인합니다.
4. 허용 판매/출처 도메인, 공식 상품별 구매 URL, 마지막 가격/재고/사이즈 확인 시각, 갱신 주기·보관/만료 기한.
5. 판매 중지·권리 철회·가격 변경 시 정정/삭제 전달 방법, 연락 담당자와 증빙 문서. 담당자 개인정보와 계약 원문은 공개 상품 파일에 넣지 않습니다.
6. 사이즈표가 **의류 실측(garment)**인지 **권장 인체 치수(body)**인지, 단위·측정 기준·오차·반품 조건. 출처가 없으면 unknown으로 표시하며 사진에서 치수를 만들지 않습니다.
7. 제휴/상업적 표시 조건과 비용이 있다면 정확한 요금·상한. 운영자가 별도 승인하기 전 가입금·유료 API·실제 수집/Cron·결제를 활성화하지 않습니다.

이 문서는 판매자 동의 계약 자체나 법률 검토를 대신하지 않습니다. 판매자가 파일에 `permissionChecked=true`라고 써도 운영자 승인이 자동 생성되지 않습니다.

## 상품 행 필드

CSV의 배열 필드는 `|`로 구분하며 JSON은 배열을 사용합니다. UTF-8 CSV와 UTC ISO 시간만 허용합니다. 추가 열/필드(회원·이메일·API 키 등)는 거부합니다.

| 필드 | 형식·필수 여부 |
| --- | --- |
| `id`, `approvalId` | 실제 판매자 상품 ID와 운영자가 지정한 승인 ID. 영문/숫자 `_ . : -`, 1–120자. 파일 안 상품 ID 중복 불가 |
| `name`, `brand` | 실제 상품명·브랜드. 160/80자 이하 |
| `category` | `tops`, `bottoms`, `outerwear`, `dresses`, `accessories` |
| `type` | `clothing`, `slacks`, `jeans`, `trousers`, `shirt`, `knit`, `jacket`, `coat`, `dress`. 모르면 `clothing` |
| `color` | 판매자가 확인한 색상. 모르면 명시적으로 `unknown` |
| `styles` | 확인된 `minimal`, `casual`, `classic`, `streetwear`. 정보 없으면 빈 배열/빈 CSV 셀 |
| `occasions` | 확인된 `work`, `casual`, `event`. 정보 없으면 빈 배열/빈 셀 |
| `gender` | 판매자가 선언한 `women`, `men`, `unisex`. 누락을 임의의 성별로 보충하지 않음 |
| `price`, `currency` | 실제 양수 가격과 `KRW/JPY/USD/EUR/GBP`. KRW/JPY 정수, 나머지 소수 둘째 자리까지. 배송·세금 미확인을 0으로 추가하지 않음 |
| `sizes` | 실제 제공 사이즈 배열/`S|M|L`. 미확인 시 빈 배열/빈 셀 |
| `sizeChart` | 아래 표 구조. 모르면 JSON `null` 또는 빈 CSV 셀 |
| `imageUrl` | 이용 허락된 실제 이미지 HTTPS URL, 별도 승인 imageDomains의 정확한 호스트만 허용 |
| `retailer` | 승인서의 판매자 명칭과 정확히 일치 |
| `purchaseUrl` | 실제 상품별 HTTPS 구매 URL, 승인 판매 호스트만 허용 |
| `sourceUrl` | 실제 판매자 자료/피드의 공개 가능한 출처 URL, 운영자 승인 sourceUrl과 일치 |
| `permissionChecked` | 판매자의 자료 제공 권한 확인 `true`. 이것만으로 공개되지 않음 |
| `lastChecked` | 실제 가격/재고/자료를 확인한 UTC 시각: `YYYY-MM-DDTHH:mm:ssZ` 또는 밀리초 포함. 미래·만료 시각 거부 |
| `stock` | 현재 `in_stock`만 공개. 미확인/품절 데이터는 가져오기 거부 |
| `tags` | 실제 확인된 `straight/relaxed/layered/balanced/tight/cropped/low-rise/logos`, 없으면 빈 배열/셀 |
| `designTagsComplete` | 디자인 항목을 충분히 확인했을 때만 `true`, 그 외 `false`. 디자인 미확인을 숨기지 않음 |

`fixture`, `demo`, 클라이언트 `sourceVerified` 등 임의의 승인/시험 플래그는 입력 필드가 아니며 거부합니다. 상품이 실제 판매 상품인지는 운영자의 출처·파일 검토가 필요하며 문자열 검증이 실제성을 증명하지 않습니다.

### 사이즈표 구조

`{"unit":"cm","kind":"garment 또는 body","rows":[{"size":"판매자가 확인한 사이즈","chest":양수,"waist":양수,"hips":양수,"inseam":양수,"shoulders":양수,"length":양수}]}`

위 구조는 **필드 안내이며 실제 상품 행이 아닙니다**. 측정값은 확보한 항목만 넣고 0을 대신 쓰지 않습니다. `size`는 `sizes`의 실제 표기와 일치해야 하며 측정값 없는 행은 허용하지 않습니다. 미확인 차트는 `null` 또는 `{"unit":"cm","kind":"unknown","rows":[]}`입니다. 의류 실측과 인체 치수의 같은 숫자를 같은 의미로 비교하거나 정확한 착용을 보장하면 안 됩니다.

CSV에서 `sizeChart`는 JSON 문자열 한 셀입니다. CSV 규칙에 따라 전체 셀을 큰따옴표로 감싸고 내부 `"`는 `""`로 이스케이프합니다. 텍스트 에디터 대신 CSV를 지원하는 도구를 써도 되지만 식별자/시간/사이즈 표기가 자동 변환되지 않았는지 확인해야 합니다.

## 운영자 승인 목록과 파일 무결성

별도의 `catalog/source-approvals.json` 구조는 다음과 같습니다. 실제 승인이 없으면 `sources:[]`를 유지합니다.

```
version: 1
sources[]:
  id: 승인 ID
  seller: 실제 판매자 명칭
  domains: 출처와 구매 URL의 정확한 HTTPS 호스트 목록
  imageDomains: 허가된 이미지 HTTPS 호스트 목록
  rightsConfirmed: 실제 증빙 검토 후 true
  displayApproved: 이 무료 베타 공개 표시 승인 후 true
  validUntil: 권리 만료 UTC ISO 시각
  evidenceRef: 비공개 증빙 참조 ID (계약·연락처 공개하지 않음)
  sourceUrl: 공개 가능한 실제 자료 출처 HTTPS URL
  retentionHours: 1–168 시간 중 승인된 자료 보관/유효 시간
  inputSha256: 운영자가 검토한 CSV/JSON 원본 바이트의 SHA-256
  productsSha256: 정규화한 해당 승인 상품 그룹의 SHA-256
```

1. 실제 권리와 출처를 먼저 확인하고 승인 메타데이터를 작성합니다. 해시는 아직 확정 전이어도 검사 명령은 가능합니다.
2. 원본 파일을 읽어보기 전 해시 승인만 하지 마세요. 실제 상품·이미지·구매 페이지·갱신 시각을 운영자가 확인해야 합니다.
3. `--inspect`로 원본·정규화 그룹의 해시를 얻습니다. 이 명령은 **공개 파일을 쓰지 않고 등록 수 0을 보고**합니다. 실제 신원·권리나 HTTP 성공을 자동 보증하지 않습니다.
4. 검토한 두 해시를 승인 목록에 정확히 입력합니다. 파일이 바뀌면 재검토·해시 승인도 필요합니다. 해시는 검토한 파일과 출력의 무결성을 고정하며 판매자 진위를 암호학적으로 증명하지 않습니다.
5. 실제 가져오기는 모든 행을 검증한 후에만 공개 JSON을 원자적으로 교체합니다. 하나라도 실패하면 기존 공개 파일을 유지합니다.
6. 공개 빌드 시 `validateSnapshot()`으로 승인 철회/만료·정규화 상품 그룹 해시·URL/필드·가격 유효성을 다시 확인합니다. 브라우저도 표시 직전에 만료된 항목을 제외해야 합니다.

```sh
node scripts/import-product-catalog.cjs --input /승인자료/판매자파일.csv --approvals catalog/source-approvals.json --inspect
node scripts/import-product-catalog.cjs --input /승인자료/판매자파일.csv --approvals catalog/source-approvals.json --output assets/approved-products.json
```

파일 경로는 사용자가 가진 로컬 경로로 바꿉니다. JSON도 같은 명령으로 지원하며 확장자를 `.json`으로 사용합니다. `--now UTC-ISO`는 격리 재현 검사에만 사용하고 운영 검토 시 현재 시각을 임의로 바꾸지 않습니다.

## 검증의 한계와 현재 상태

가져오기 스크립트는 네트워크·쇼핑몰·운영 DB를 호출하지 않습니다. HTTPS·허용 도메인·자격 증명/리디렉션 파라미터·시각·필드/차트·승인 해시를 검증하지만 이미지가 실제로 열리는지, URL이 현재 판매 중인지, 가격/사이즈가 맞는지는 판매자 자료와 운영자 확인이 필요합니다. HTTP 검증을 하지 않은 상태를 성공했다고 표시하면 안 됩니다.

현재 실제 승인/상품 자료가 없으므로 등록 수는 **0개**입니다. 단위·브라우저 검사의 synthetic fixture는 임시 검사에만 쓰며 실제 공개 파일에 포함하지 않습니다. 실제 10개 목표는 승인된 자료를 받은 후에만 완료할 수 있습니다. 회원/Firebase/구독/운영 DB·main·Production·결제·유료 API·외부 사진 처리·API 격리를 변경하지 않습니다.

## 현재 구현 연결과 운영 제한

현재 한 공개 스냅샷은 최대 100개 상품을 처리합니다. 입력 CSV/JSON의 모든 행을 검증하며 일부만 조용히 공개하지 않습니다. 가져오기 때 원본 파일 해시를, 빌드 때 정규화된 공개 상품 그룹 해시를 각각 검증합니다. 공개된 빈 목록은 실제 등록 상품 0개이며 모든 예시/테스트 파일과 분리돼 있습니다.

홈의 검색은 카테고리·의류 종류·색상·컬렉션·통화·예산·사이즈를 적용하고 기존 점수 엔진의 이유/주의사항을 표시합니다. 규칙 상담은 동일한 등록 상품 결과를 참조합니다. 비교는 최대 4개까지이며 직접 입력한 치수와 판매자 표의 수치 차이만 보여 줍니다. 표의 의류 실측과 신체 기준을 구분하고 소재·여유분 때문에 사이즈 적합 판정을 하지 않습니다. 사진 비율은 별도 동의 후 참고 규칙에만 사용하고 실제 cm를 생성하지 않습니다. 원화 예산을 다른 통화로 자동 환산하지 않습니다.

이 단계는 판매자가 파일을 제공하면 운영자가 증빙/파일을 검토한 후 가져오고 개발 Preview로 배포하는 경로입니다. 일반 사용자가 브라우저에서 CSV를 업로드해 공개 권한을 얻는 기능이나 운영 DB 등록 API를 만들지 않았습니다. 실제 배포는 기존의 별도 승인 정책을 유지합니다.

정적 Preview 공개 범위도 판매자와 확인해야 합니다. 새 빌드에서 철회 상품을 제거해도 과거 고정 Preview 주소의 JSON이 자동 삭제되는 것은 아닙니다. 화면의 만료 제외와 원본 파일 삭제는 다르며, 보관/철회 조건이 요구하면 운영자가 과거 배포 제거까지 수행해야 합니다. 현재 공개 자료는 빈 목록이므로 실제 상품 보관/철회 문제가 발생하지 않았습니다.

철회는 해당 source의 공개 상품 그룹을 전체 제거하고 승인 항목을 제거한 뒤 새 Preview 검증으로 반영합니다. 승인 플래그만 false로 바꾸고 기존 공개 상품을 그대로 두면 빌드는 차단됩니다.

## 이번 구현 검증

- 실제 공개 `assets/approved-products.json`은 0개, 승인 목록도 0개입니다. CSV/JSON 양식에는 상품 행이 없습니다.
- 전체 자동 검사 245개 통과. 원본 파일 변경·공개 그룹 내용 변조·허가 부재·철회·미허용 URL·미래/만료 시각·잘못된 사이즈표·CSV 인용 처리·실패 시 기존 출력 보존을 검증했습니다.
