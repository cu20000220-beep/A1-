# 실사 스타일 이미지 스튜디오

사용자는 공유한 에이든 결과물이 연속 회전하는3D가 아니라 **여러 방향의 이미지**라고 확인했다. 그 방식에 맞춰 참고 이미지의 자연스러운 남녀 인물·니트/의류 질감·밝은 스튜디오 분위기를 가진 정적 이미지 자산과 실제 선택 가능한 화면을 구현했다.

작업 중 원격에 추가된 `242f06d`의 [구현 지시서](A1-FASHION-3D-REFERENCE-IMPLEMENTATION.md)를 fast-forward로 반영했다. 해당 문서의 실제3D 통합 요구를 기존 GLB 뷰어 재사용으로 구현하며, 색상/배치는 이번 대화에 실제 첨부된 흰 배경 시안을 기준으로 했다.

진입점은 `fitting-studio.html`이다. 홈 CTA·공통 서비스 메뉴·기존3D페이지에서 들어갈 수 있다. 남녀 가상 모델을 고르고 기본 의상을 정면/사선/측면/후면으로 확인하거나, 모델별5개 의상 이미지를 선택한다. 의상별 이미지는 정면만 있으므로 다른 방향 버튼을 비활성화하며 기본 의상으로 돌아가면4방향을 다시 제공한다. 초기화·이미지 실패 표시·수동 재시도를 지원한다.

실패 복구 검사에서 preload만 성공하고 CSS 배경은 실패 캐시에 남아 인물이 빈칸으로 보이는 문제를 직접 재현했다. 실패한 모델을 다시 선택할 때 preload와 모든 해당 sprite가 같은 새 버전의 고정 동일 출처 URL을 사용하도록 수정했다. 재시도·초기화·모델 재선택 모두 같은 복구 경로를 사용하며 자동 반복 요청은 없다. 모바일에서 화면 아래 의상 카드를 눌러도 바뀐 인물이 바로 보이도록 선택 후 결과 이미지로 이동하며, 동작 줄이기 설정을 존중한다. 초기 페이지 로딩에는 자동 스크롤하지 않는다.

## 이미지와 기능의 정확한 범위

- `assets/studio/hero.png`: 본 프로젝트를 위해 생성한 남녀 모델 이미지.
- `male-sheet.png`·`female-sheet.png`: 각각3×3 프레임. 기본 의상4방향과 정면 스타일5종이다. 제작한 가상 성인 인물이며 실제 상품·판매처 사진이 아니다.
- 원본 생성 이미지를 편집하거나 잘라 쓰지 않고 CSS의 고정3×3영역으로 표시한다. 파일 크기/실제 픽셀/해시는 `assets/studio/manifest.json`에 기록한다.
- 화면에 **스타일 이미지 미리보기 · 2D**, **예시 의상 · 실제 상품 아님**을 계속 표시한다. 이미지 교체를 실제3D회전·실시간AI판단·사용자사진합성·사이즈보장으로 표현하지 않는다. 사진에서 키/체중을 측정한 것처럼 예시 숫자를 만들지 않는다.
- 실제3D stock인체는 기존 `gltf-proof.html`에 보존하고, 같은 스튜디오의 **실제3D인체샘플** 모드에서도 기존 GLB 로더를 지연 재사용한다. iframe으로 보호 헤더를 우회하지 않는다. 이 실사 이미지 속 인물을 실제3D모델로 변환한 기능은 아직 없으며3D모드는 다른 샘플임을 명시한다.
- 기존 사진 분석, 동의 기반 로컬2D배치, 무료 규칙 스타일리스트, 국내 검색으로 연결한다. 개인화·상품연동 상태를 바꾸거나 새 상품/가격을 생성하지 않는다.

## 보호·비용

이미지는 개발 중 사용자 요청으로 제작한 정적 자산이다. 운영 앱에서 이미지 생성·사진 외부 전송·유료 AI/API를 호출하지 않는다. 이미지 모드는 정적 이미지·스크립트·CSS만 읽으며 서버/API/회원 데이터와 연결하지 않는다. 선택한3D모드의 고정 GLB·manifest 읽기를 위해 새 페이지에만 기존3D뷰어와 같은 `connect-src 'self'`, `img-src 'self' blob:`를 적용한다. 기존 페이지의 CSP·Preview API503 보호를 유지한다. 개인 사진·신체 치수 입력이나 저장소를 추가하지 않았고, 기존 언어 선택기의 언어 설정만 사용한다.

기존 무료 정책·Preview API503 격리·서버 회원별 권한·회원/구독 기록·Firebase/DB를 유지한다. main 병합·Production 배포·Cloudflare 로그인/운영 설정 변경은 하지 않는다.

## 검증

`node tests/fitting-studio-browser.cjs`로1440데스크톱·820태블릿세로·1180가로·390모바일의 한국어/영어를 확인한다. 실제 이미지 픽셀과 방향/모델/스타일의 차이, 앞면만 있는 의상의 방향 제한, 초기화·오류/수동 재시도, 기존기능링크, 개인 저장소 보존과 외부/API요청 부재·CSP를 검사한다. 실제 iPad Safari 하드웨어 검증은 아니다.

최종 브라우저 검사는5개 화면 조건과 재시도/초기화 양쪽의 실제 이미지 복구를 통과했다. 이미지 변경 후 테스트의 screenshot 자동 스크롤 전에 실제 사용자 viewport에 결과가 보이는지도 검사했다. 태블릿에서는 같은 페이지에서 실제3D를 열어73관절·실제 텍스처·40,000개 이상 삼각형과 서로 다른 전/측/후면 픽셀을 확인하고, 이미지 모드 전환 시 GPU geometry/texture가0이 된 뒤 다시3D를 시작할 수 있음을 검증했다. renderer를 재작성하거나 iframe/CSP 우회로 표시하지 않았다.
