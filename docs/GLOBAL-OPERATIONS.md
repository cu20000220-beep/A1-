# 글로벌 플랫폼 운영 승인과 비용 관리

현재 운영 중인 A1 FASHION Pages 프로젝트, Firebase 회원 식별자 `(issuer, subject)`, 기존 사진 분석과 한국어·영어 UI를 유지합니다. 이번 확장은 Pull Request에서 검토하며, 코드 작성·테스트만으로 운영 DB, 결제, 피드 수집, 정기 실행이나 알림 발송을 활성화하지 않습니다.

## 이번 변경의 구현 범위

기존 화면에서 글로벌 쇼핑으로 이동하고, 글로벌 쇼핑·멤버십·가격 비교·관심 상품·프로모션 알림·내 계정의 여섯 화면을 한국어/영어로 이용하도록 확장합니다. 기존 이메일 회원가입·로그인·무료 사진 분석은 유지합니다. 국가·배송 목적지, 다섯 통화와 검색 필터를 지원하며 판매처는 검색 연결과 실제 상품 피드를 구분합니다.

서버에는 FREE/GENERAL/PREMIUM 권한 검사, 회원별 관심 상품·목표 가격·알림 설정·채널별 동의/철회·모의 이력의 접근 통제를 구현합니다. 상품 변형·비용·갱신 시각·환율을 검사하는 가격 비교 엔진과 명시적인 DEMO 자료, 실제 발송 없는 알림 조건·템플릿·중복 방지, 승인 전 비활성화된 공급자 어댑터와 수동 Worker 구조를 포함합니다.

정적 빌드는 글로벌 공개 화면 파일만 허용 목록에 추가합니다. 서버 상품 자료·예약 Worker·비밀값은 공개 출력에 복사하지 않습니다. 기존 D1 스키마와 세 개의 검토용 마이그레이션을 제공하지만 운영 DB에는 적용하지 않습니다. 유효 구독이 없는 운영 회원에게 테스트용 유료 권한을 만들지 않습니다.

## 운영 모드

- **모의 모드:** 허구의 상품·가격·프로모션을 DEMO로 표시합니다. 이메일/SMS 템플릿과 모의 이력만 다루며 실제 메시지는 보내지 않습니다.
- **검색 연결:** 판매처의 검색 화면으로 이동합니다. 개별 상품을 실시간으로 가져온 것, 배송 가능이 확인된 것, 제휴 승인을 받은 것으로 표시하지 않습니다.
- **승인된 실제 피드:** 공급자 승인·약관·인증·저장/갱신 정책을 확인한 어댑터만 대상에 넣습니다. 검색 링크만 있는 판매처를 자동 감시하지 않습니다.
- **실제 발송:** 이번 어댑터는 실제 전송 구현을 제공하지 않는 HARD DRY_RUN입니다. 별도의 운영자 승인 후 제공자 전송·수신 거부·반송 처리 구현을 검토해야 하며 환경 플래그나 키의 존재, API 요청의 `live` 표시, 브라우저 구독 값만으로 전환할 수 없습니다.

## 회원 등급과 기존 회원

FREE는 회원가입·로그인·사진 분석 및 서비스 안내를 이용합니다. GENERAL은 유효한 결제 기록이 있을 때 추천과 국내·해외 판매처 검색 연결을 이용합니다. PREMIUM은 유효한 프리미엄 기록이 있을 때 가격 비교와 알림 기능을 추가로 이용합니다. 서버는 서명 검증된 사용자와 현재 구독 행을 매 요청마다 확인해야 합니다. 언어·국가·통화 선택은 권한의 근거가 아닙니다.

**기존 유료 회원 이전 제안:** 과거의 유효한 유료 기록은 기존 추천 이용권에 대응하는 GENERAL로 취급하고, PREMIUM으로 자동 올리지 않습니다. `plan_code` 기본값과 이전 대상/제외 조건을 운영자가 승인한 뒤 마이그레이션을 적용합니다. 승인 전 운영 데이터를 갱신하지 않습니다. 기존 DB에 등급 열이 없을 때의 호환 경로도 실제 DB 상태와 함께 검토합니다. 만료·환불·미납·취소·결제 검증 없는 행은 새 등급 부여 근거가 아닙니다.

월 구독료는 미정입니다. 이 변경으로 실제 정기 청구나 시험 결제를 만들지 않습니다. 향후 가격·반복 제공 혜택·해지/환불 조건과 결제 제공자 승인이 확정되어야 합니다.

## 현재 0원으로 확인할 수 있는 범위

정적 화면·준비 번역·기기 내 사진 분석, 로컬 SQLite/D1 대역·workerd 테스트, DEMO 상품 비교, 알림 조건/템플릿/중복 방지의 모의 실행을 확인할 수 있습니다. 기존 Firebase Spark 및 Cloudflare 무료 플랜의 한도 안에서 회원 기능을 운영할 수 있지만 무제한 운영을 보장하지 않습니다. 무료 한도 근거는 [공식 자료 조사](GLOBAL-RESEARCH.md)를 참고하세요.

추가되는 규모 비용은 Functions/Worker 요청과 CPU, D1 조회·쓰기·이력 보관, 공식 피드/제휴 계약, 환율 자료, 발송 도메인, 이메일 발송량, SMS 국가별 단가·메시지 분할·번호 유지·발신자 등록, 반송/신고 처리 및 운영 인력입니다. 현재 확인하지 않은 요금을 0원으로 간주하지 않습니다. 유료 업그레이드나 카드 등록은 운영자 승인 없이 진행하지 않습니다.

## 실제 데이터와 가격 비교 승인

1. 상품 공급원별 API/피드 사용 승인과 인증키를 준비합니다. 키는 서버 환경에만 입력하고 채팅·정적 파일·Git에 넣지 않습니다.
2. 이미지 권한, 제휴 표기, 저장 가능 기간, 가격 갱신 간격, 대상 국가와 marketplace를 기록합니다.
3. GTIN 또는 판매자가 확인한 브랜드/SKU 식별자와 색상·사이즈·상태를 비교합니다. 유사 디자인은 동일 상품 묶음에서 분리합니다.
4. 원 가격·통화·배송비·알려진 세금/관세와 미확인 항목을 구분합니다. 미확인 비용을 0으로 대체하지 않습니다.
5. 갱신 시각·품절 여부·환율 출처/시각을 검사합니다. 오래되거나 불완전한 자료는 최저가 배지의 근거로 삼지 않습니다.
6. 결과는 ‘확인된 판매처 중 최저 예상 구매가’처럼 제한된 범위를 표시합니다. 전 세계 절대 최저가 또는 최종 결제 총액을 보장하지 않습니다.

## 동의와 개인정보

이메일과 SMS의 광고 수신 동의는 서로 분리하고, 회원가입·구독 결제 동의와도 분리합니다. 새 문안 버전을 확인한 동의는 당시의 수신 국가 설정·문안 언어·정확한 문안과 시각을 별도 감사 기록에 보관합니다. 이후 설정 변경으로 과거 문안을 덮어쓰지 않습니다. 구버전 기록은 당시 문안을 알 수 없는 상태로 남기며, 실제 발송 전 법적 동의 증빙·보관 요건은 별도 승인해야 합니다. 관심 상품/브랜드, 알림 빈도, 시간대와 목표 가격은 해당 회원의 `(issuer, subject)`로만 조회·갱신합니다. 다른 회원 ID를 요청에 넣어 접근할 수 없어야 합니다.

가입 시 확인된 이메일을 사용하더라도 마케팅 수신 동의가 있는 것으로 간주하지 않습니다. E.164 형식 검사에 통과한 전화번호도 소유 확인을 마친 번호로 간주하지 않습니다. 원본 사진, 전체 인체 기준점, 체형 분석 수치는 발송 제공자·마케팅 템플릿에 전달하지 않습니다.

발송 직전에 현재 PREMIUM 유효기간, 현재 채널 동의와 주소/번호 확인, 차단/반송 상태, 빈도·시간대·예산을 다시 확인합니다. 대기열 작성 후 철회된 동의로 발송하면 안 됩니다. 회원·이벤트·채널·시간 창을 기준으로 원자적으로 중복을 차단하고, 소유자 범위의 이력을 남깁니다.

관심 목록·설정·이력 조회와 수신 철회·삭제는 구독 만료 후에도 본인 로그인 확인으로 가능합니다. 회원 탈퇴는 비밀번호로 같은 계정임을 재확인한 뒤 글로벌 관심 목록·설정·연락처·동의·모의 기록을 먼저 지우며, 이 삭제가 실패하면 Firebase 계정을 먼저 삭제하지 않습니다. 금융 거래의 보관 범위는 분리합니다.

수신 거부는 로그인 강요 없이 처리할 수 있는 서명된 운영 링크 등 검증된 흐름을 마련해야 합니다. 모의 템플릿의 자리표시자 URL은 실제 수신 거부 기능이 아닙니다. 철회는 새 발송을 즉시 막고 대기 항목을 취소해야 합니다. 기록 삭제/회원 탈퇴 요청에는 관심 목록·알림 설정·연락처의 삭제와, 법적 보관이 필요한 최소 동의/거래 기록의 분리·보관 기한을 운영자가 확정합니다. 삭제 요청을 이유로 새로 마케팅 동의를 만들지 않습니다.

## 준비 단계에 남아 있는 구현

- 승인된 기존 D1 상품을 탐색·비교하는 읽기 전용 경로는 완성했습니다. ENABLE_LIVE_CATALOG와 GLOBAL_CATALOG_APPROVED가 모두 true여야 읽으며 기본값에서는 조회하지 않습니다. 실제 수집기나 제휴 승인을 자동으로 만들지 않습니다. eBay 어댑터는 승인/키가 없는 기본 상태에서 비활성화됩니다. Awin은 승인된 광고주 피드의 정확한 매핑이 준비되지 않아 실제 수집을 실행하지 않습니다. 현재 기본 화면은 검색 링크 또는 명시적인 DEMO이며, 운영에 승인된 공식 상품을 등록한 뒤에만 검증 상품 화면을 사용할 수 있습니다.
- 알림 API에는 본인 관심 상품·목표 가격·관심 브랜드/카테고리·채널별 동의로 다섯 가지 DEMO 조건을 평가하고 기존 D1 이력에 원자적으로 기록하는 모의 실행을 연결했습니다. 일/주 요약의 중복 방지는 동작하지만 실제 지정 시각 전달, 공급자 발송 큐·피드 자동 갱신·실제 발송량과 비용 원장은 활성화하지 않습니다. 예약 Worker는 기존 수동 구조를 유지합니다.
- 이메일/SMS 제공자 어댑터는 실제 전송 코드가 없습니다. 검증된 도메인·연락처, 운영 수신 거부와 반송/차단 연동, 전화번호 소유 인증, 국가별 발신 등록과 실제 비용 자료는 향후 별도 구현·승인이 필요합니다. 모의 템플릿의 링크는 운영 수신 거부 링크를 대신하지 않습니다.
- 동의 당시 국가·언어·문안 스냅샷은 검토용 0003 마이그레이션과 새 문안 확인 후 기록합니다. 구버전 DB에서는 정확한 누락 열에 한해 기존 저장 방식으로 동작하고 증빙 누락을 표시합니다. 오래된 문안 버전이나 요청 한도 초과도 수신 철회를 막지 않습니다. 법적 보관 기간과 실제 발송 적합성은 별도 승인 항목입니다.

## 예약 실행 승인

Pages Functions와 별도의 예약 Worker를 구분합니다. 초기에는 Cron을 등록하지 않고 관리자가 제한된 데이터로 수동 실행합니다. 가격을 실제로 제공하는 승인된 공급원만 갱신하고, 운영 예약 전에는 한 번의 작업에서 상품 수·요청 수·DB 행 수·CPU/실행 시간의 제한을 추가 검증합니다. 현재 수동 구조는 소수의 승인된 공급원과 모의 후보만 처리하며 실제 무료 CPU 사용량을 측정한 운영 작업이 아닙니다. 장기 실패·429·쿼터 부족 시 재시도를 늘리지 않고 중지/지연합니다.

실제 예약을 켜기 전에는 빈도, 배치 크기, 공급자별 갱신 제한, D1 일간 읽기/쓰기·저장 예산, 알림 상한, 실패 중단 조건, 보관 기간과 복구 방법을 승인합니다. 가격·프로모션·전송 이력의 정리는 공급자 계약과 개인정보 보관 정책에 맞춰야 하며 임의로 운영 데이터를 삭제하지 않습니다.

## 배포를 위한 정확한 승인 순서

1. **코드 검토:** Pull Request의 화면, 권한/격리 테스트, DEMO 표시와 모의 발송 기본값을 검토합니다. PR 생성·Preview는 운영 DB 적용이나 결제를 승인하는 행위가 아닙니다.
2. **기존 회원 정책:** 현행 회원을 읽기 전용으로 분류한 결과와 GENERAL 이전안을 검토합니다. 승인 전 기존 회원의 등급·이용 기간을 갱신하지 않습니다.
3. **DB 적용:** 운영 D1 바인딩과 대상 DB를 식별하고 백업/복구 계획, 로컬 마이그레이션 검증, 승인된 SQL 목록을 확인한 후 별도 승인합니다. 기존 기록 삭제는 포함하지 않습니다.
4. **기본 배포:** 승인된 PR만 main에 병합합니다. 현재 Pages 프로젝트를 유지하며 회원·사진 기능의 실제 회귀를 확인합니다. 알림은 계속 DRY_RUN이고 상품도 DEMO/검색 링크 상태입니다.
5. **공식 상품 연결:** 공급자/광고주별 승인·이용 조건·서버 키와 비용 한도를 확인한 후 개별 어댑터를 활성화합니다. 실물 상품의 가격/재고/이미지와 지역별 URL을 검증합니다.
6. **알림 연결:** 이메일·SMS를 각각 별도 승인합니다. 이메일은 도메인 인증·검증된 주소·독립 동의·수신 거부·반송 차단·빈도 상한을 확인합니다. SMS는 검증된 번호·현지 발신 등록·단가·월 비용 상한·별도 동의를 추가 확인합니다. 승인 전 시험 문자나 실발송을 하지 않습니다.
7. **자동화 연결:** 수동 실행의 무료 한도 측정 결과와 실패/철회/중복 처리 검증을 본 뒤 예약 Worker 배포 및 Cron 빈도를 별도 승인합니다.
8. **결제 연결:** 월 구독료·혜택·해지/환불·제공자 요건을 결정한 뒤 별도 승인으로 구현·검증합니다. 이번 PR에는 청구 활성화 권한을 포함하지 않습니다.

승인 대상에는 작업명·대상 환경·예상 비용 상한·중단 방법을 명시합니다. 모의 실행 결과나 단순 API 키 입력을 실제 발송/청구 승인으로 해석하지 않습니다.

## 검증 범위

회원 권한·회원별 데이터 접근·DB 마이그레이션 보존·상품 변형과 비용 처리·동의/철회·중복 방지는 외부 서비스 호출 없는 테스트 자료로 자동 검증합니다. 브라우저에서는 한국어/영어, 스마트폰·태블릿·PC 크기 화면, 기존 회원/사진 기능과 글로벌 화면을 검사합니다. 테스트용 유료 회원은 로컬 자료에만 존재하며 운영 회원을 만들지 않습니다.

실제 iPad Safari 기기, 운영 Firebase 이메일 수신, 공식 상품 피드 승인, 실제 이메일/SMS 전달, 실제 유료 결제는 로컬 Chromium·모의 공급자 테스트와 별도입니다. 이 작업은 후자의 운영 시험을 수행하지 않습니다. 코드 검토 단계의 테스트 통과를 실시간 상품 연동·운영 마케팅·가격 보장으로 표현하지 않습니다.
