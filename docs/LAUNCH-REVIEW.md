## 확인한 실제 오류와 수정

프리미엄 목표 가격 저장 중 PREMIUM에서 GENERAL로 변경되면, 기존 코드는 시작 시점 등급만 확인한 뒤 GENERAL로 최종 검사해 목표 가격을 저장할 수 있었습니다. 실제 RSA와 SQLite를 사용한 지연 쓰기 재현에서 GENERAL 상태로 목표 가격이 저장되고 HTTP 201이 반환됐습니다. 응답만 403으로 바꾸면 부적절한 데이터가 남으므로 쓰기 자체의 현재 권한 검사와 회귀 테스트를 추가했습니다. 일반 찜은 현재 GENERAL 이상, 목표 가격·알림 설정·새 마케팅 동의는 현재 PREMIUM을 INSERT/UPDATE SQL 안에서 검사합니다. 요청 시각과 SQLite 실행 시각 중 늦은 값을 사용합니다. 목표 가격 응답은 마지막에도 PREMIUM을 재검증합니다. 철회·삭제·유효한 기존 GENERAL 호환과 목록 100개 제한을 유지했습니다. 신규 회귀 검사 11개는 수정 전 10개 실패, 수정 후 모두 통과했습니다. 기존 이메일·SMS 템플릿 미리보기 저장의 권한 검사도 같은 SQL 시각 기준을 재사용합니다. 새 DB 마이그레이션은 필요하지 않습니다.

Preview 계정 화면에서 의도적인 `preview_isolated` 차단을 일반 재시도 오류로 표시하던 안내도 수정했습니다. 이 경우에만 명시적인 한·영 Preview 설명을 표시하고 재연결 버튼을 숨깁니다. Production의 일반 설정·네트워크 오류 처리와 Firebase 흐름은 유지합니다.

## 운영 D1의 정확한 적용 경로

현재 운영 DB 존재·ID·이름·바인딩·스키마·이력·백업은 미확인입니다. 다음 표는 적용 계획이며 실행한 운영 작업이 아닙니다.

| 확인된 실제 상태 | 검토할 SQL |
| --- | --- |
| DB 없이 기존 무료 Firebase 회원/분석만 제공 | SQL 불필요. 유료 기능은 잠김 |
| plan_code 없는 초기 memberships DB | 미적용 0001 → 0002 → 0003 → 0004 |
| 글로벌 0002까지 적용 | 미적용 0003, 0004 |
| 글로벌 0003까지 적용 | 미적용 AI 0004 |
| 완전히 빈 승인된 DB | server/schema.sql 다음 AI 0004만 적용 |

`0001_membership_tiers.sql`과 `0003_global_consent_context.sql`의 ALTER는 중복 실행하지 않습니다. `0002`/`0004`의 IF NOT EXISTS도 기존 구조가 올바른지 확인하는 기능이 아닙니다. 적용 이력과 실제 열·테이블·트리거를 함께 확인하고 필요한 SQL만 검토합니다. 기존 DB에 전체 schema.sql과 ALTER를 중복 적용하지 않습니다. 도구를 사용할 경우 정확한 대상 DB ID/이름과 `migrations_dir: "server/migrations"`를 명시하고 ledger를 확인합니다. 이 저장소의 SQL을 기본 migrations 폴더로 오인하지 않습니다.

기존 유효 유료 기록은 GENERAL로 호환하고 자동 PREMIUM 승격하지 않습니다. 과거 동의의 증빙 없는 국가·언어·문안은 null로 보존합니다. 마이그레이션은 결제·GPT·발송·Cron이나 시험 구독을 생성하지 않습니다. 신규 저장 권한 보완에 새 운영 SQL은 필요하지 않습니다.

## 백업·복구 계획

1. 승인된 대상의 DB ID/이름, 환경, 바인딩, 현재 스키마/ledger, 회원·찜·동의 등 주요 행 수와 백업 시각을 기록합니다.
2. 대상·정확한 SQL·기존 등급 이전·쓰기 중단 여부를 검토하고 **운영 DB 작업의 별도 승인**을 받습니다.
3. SQL 내보내기와 현재 Time Travel 복구 시각/bookmark를 확보합니다. 실제 DB의 지원 여부·계정 한도를 확인합니다. 공식 문서의 Free 복구 기간은 7일이며 Paid의 30일과 혼동하지 않습니다. 해당 기능의 실제 이용 가능 여부를 확인하기 전 복구 가능하다고 약속하지 않습니다.
4. 승인된 격리 DB에서 백업 복원·무결성·행 수·회원/구독/동의 보존과 누락 SQL 적용을 먼저 확인합니다. 기존 회원을 무단으로 시험 환경에 복제하지 않습니다.
5. 승인된 SQL만 운영에 한 번씩 적용하고 결과를 ledger에 기록합니다. 실패하면 쓰기를 중단하고 승인된 복구 절차를 따릅니다. Time Travel 복원은 대상 DB를 제자리에서 덮어쓰므로 자동 실행하지 않습니다. 복구 시점 이후의 철회·삭제 요청도 재반영합니다.

코드 rollback은 DB 복원과 별개입니다. 기존 정상 Production은 사용자 화면상 커밋 `67d229a`, 배포 ID 접두사 `42f5e950`입니다. 실제 전체 ID·정상 상태를 먼저 기록하고, 실패 시 Cloudflare Deployments에서 그 배포를 rollback 대상으로 선택합니다. 코드 rollback이 D1/Firebase를 되돌리지는 않습니다. main 강제 reset/push, SQL DROP 또는 자동 역마이그레이션을 하지 않습니다.
