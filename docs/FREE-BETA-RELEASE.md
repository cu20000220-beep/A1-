1. 기존 공개 쇼핑 화면은 맞춤 검색 API가 GENERAL 전용이어서 무료 방문자가 사용할 링크가 없었습니다. 기존 `RETAILERS`와 URL 생성 함수를 재사용해 국가별 **중립적인 기본 검색 링크만 HTML에 추가**했습니다. 로그인·API·DB 없이 표시되며 회원·사진·분석·예산·개인화 조건을 외부 URL에 넣지 않습니다. 링크는 실제 상품·가격·재고·배송 확인·제휴 승인 결과가 아닙니다. 유료 API를 FREE로 바꾸지 않았습니다.
2. 공통 한·영 무료 베타 안내와 홈페이지 기본 검색 진입을 추가했습니다. 기존의 포괄적인 ‘모든 판매처 연결은 구독 전용’ 안내를 개인화 추천·맞춤 검색으로 좁혔습니다. 결제 준비 중/DEMO/모의 발송 표시를 유지합니다.
3. 기존 Firebase·회원 식별자·비밀번호·운영 설정을 변경하지 않았습니다. 새 구독/체험 기록이나 운영 SQL도 생성하지 않았습니다. 원본 사진은 브라우저 안에서 처리합니다.

## 별도 Worker a1

`a1fashion` Pages와 별도 Worker `a1`을 구분합니다. 사용자가 제공한 과거 Worker 로그에서는 `npx wrangler preview`의 `previews` 설정 부재로 실패했습니다. 최신 원시 로그·현재 Worker 설정은 직접 재검증하지 못했습니다. Pages의 실제 성공이 확인돼 해당 실패가 그 Preview 배포를 막은 것은 아닙니다. PR 병합 필수 검사인지 여부는 저장소 관리자 화면에서 확인해야 합니다. 무관한 Worker 설정을 수정하거나 실패 검사를 삭제·우회하지 않았습니다.

## iPad에서 마지막으로 확인할 항목

1. **새 Preview 링크를 열기:** 상단 FREE BETA/미리보기 안내, 한/영 유지, 무료 분석의 사진 선택→분석→지우기, 글로벌 공개 링크 11개와 잘림 여부를 확인합니다. 링크를 눌러 실제 외부 쇼핑몰로 이동할 때는 배송·재고·가격을 해당 판매처에서 확인합니다. Preview의 회원가입/로그인 503은 의도한 보호이며 Production 가입 실패가 아닙니다.
2. **Cloudflare → Workers 및 Pages → a1fashion → 설정:** Git 저장소 유지, Production main, 빌드 `node scripts/build-site.cjs`, 출력 dist를 확인합니다. ‘변수 및 비밀’에서 기존 `FIREBASE_PROJECT_ID`·`FIREBASE_WEB_API_KEY`를 그대로 유지합니다. 키 값을 채팅이나 공개 저장소에 올리지 않습니다. 현재 UI에서 환경 선택 위치는 확인되지 않았으므로 기존 값을 삭제하거나 임의로 다른 환경에 복제하지 않습니다.
3. **실제 호출 설정:** `A1_AI_MODE`는 미설정 또는 demo, `A1_AI_LIVE_APPROVED`, `ENABLE_LIVE_CATALOG`, `GLOBAL_CATALOG_APPROVED`, `A1_AI_CATALOG_APPROVED`는 미설정/false를 확인합니다. 새 키·결제·Cron·발송 설정은 넣지 않습니다. 기존 값이 다르면 먼저 검토하고 자동 변경하지 않습니다.
4. **바인딩:** 무료 베타를 위해 D1을 추가하거나 SQL을 적용하지 않습니다. 기존 바인딩/데이터도 삭제하지 않습니다. Preview의 모든 `/api/*`는 환경/DB/외부 서비스를 읽기 전에 차단되지만, 이것이 Cloudflare의 실제 환경별 바인딩 분리를 확인했다는 뜻은 아닙니다.
5. **GitHub PR #1 → Checks/병합 영역:** 최신 GitHub 검사·Pages 성공과 별도 Worker 실패를 구분합니다. Worker가 필수 검사로 병합을 막으면 강제로 병합하거나 검사를 제거하지 말고 관리자가 연결 목적/검사 정책을 확인해야 합니다.

기존 운영 Firebase 가입·로그인은 소유자가 앞서 성공을 확인했고 이번 작업은 해당 서버 흐름과 운영 값을 교체하지 않았습니다. 확인한 내용을 반복 입력하거나 회원 데이터를 옮길 필요는 없습니다.
