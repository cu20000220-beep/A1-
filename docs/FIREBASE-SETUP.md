# 회원가입 연결 안내 — Firebase 무료 플랜

A1에는 이메일 회원가입·이메일 인증·로그인·로그아웃·비밀번호 재설정·회원탈퇴를 Firebase Authentication에 연결하는 코드를 준비했습니다. 소유자는 Firebase 프로젝트 생성·인증 설정과 Cloudflare 운영 변수 저장을 진행했습니다. **아직 운영 사이트의 실제 가입·이메일 수신·로그인은 확인 전입니다.** 새 운영 배포와 실제 가입 확인이 끝나야 연결 완료로 판단합니다.

사진 분석은 회원가입 없이 계속 이용할 수 있습니다. 무료 회원가입만으로 의류 추천이나 쇼핑몰 연결 권한이 생기지는 않습니다. 구독 결제와 유료 이용권 연결은 별도 단계이며 현재 청구하지 않습니다.

## 현재 설정 진행 상황

- Firebase 프로젝트 `a1-fashion` 생성, 이메일/비밀번호 인증 사용, 승인 도메인 `a1fashion.pages.dev` 추가는 소유자가 보낸 화면에서 확인했습니다.
- 소유자가 웹 앱 등록과 Cloudflare Pages `a1fashion`의 Production 변수 `FIREBASE_PROJECT_ID`, `FIREBASE_WEB_API_KEY` 저장을 완료했다고 알렸습니다. 실제 키 값은 채팅이나 저장소로 받지 않았습니다.
- 저장한 환경 설정을 적용하도록 새 Git 배포를 진행합니다. 배포 성공과 실제 인증 연결 성공은 구분하며, 사이트의 가입·인증 메일·로그인 확인이 남아 있습니다.
- 구독 결제·정기 청구·유료 회원 발급은 활성화하지 않습니다.

## 1. Firebase 프로젝트 만들기

1. iPad의 Safari에서 [Firebase 콘솔](https://console.firebase.google.com/)을 열고 사용할 Google 계정으로 로그인합니다.
2. **프로젝트 만들기 / 프로젝트 추가**를 누릅니다.
3. 프로젝트 표시 이름을 `a1-fashion`으로 입력합니다. 실제 프로젝트 ID에는 뒤에 다른 문자가 붙을 수 있으므로 나중에 표시되는 값을 그대로 사용합니다.
4. Google Analytics 사용 여부가 나오면 이 사이트에서는 **사용하지 않음**으로 진행합니다.
5. 프로젝트를 만듭니다. **Spark 무료 플랜**을 유지하고, Blaze 업그레이드·카드 등록·결제 계정 연결은 진행하지 않습니다.

Authentication의 이메일·비밀번호 방식만 연결합니다. 전화번호/SMS 인증, Firestore, Storage, Firebase Functions를 새로 설정할 필요는 없습니다. 무료 플랜에도 가입·이메일 발송 등의 한도가 있으므로 현재 프로젝트에 표시되는 한도를 확인합니다. 무제한 무료 운영을 약속하는 설정은 아닙니다.

## 2. 이메일·비밀번호 가입 켜기

1. 프로젝트에서 **빌드(Build) → Authentication**을 엽니다.
2. 처음이면 **시작하기(Get started)**를 누릅니다.
3. **로그인 방법(Sign-in method)**에서 **이메일/비밀번호(Email/Password)**를 선택합니다.
4. 이메일/비밀번호 사용을 켜고 **저장**합니다. 이메일 링크 방식이나 전화번호 방식은 켜지 않아도 됩니다.
5. **Authentication → 설정(Settings) → 승인된 도메인(Authorized domains)**에 `a1fashion.pages.dev`를 추가합니다. 도메인만 입력하며 `https://`나 `/#membership`은 넣지 않습니다.

기본 Firebase 인증·비밀번호 재설정 이메일을 사용합니다. 사용자에게 보내는 메일을 확인할 때 발신 이름과 링크의 목적이 A1 가입 안내임을 알아볼 수 있도록 점검합니다. 이메일 전송 한도에 걸리면 가입이나 인증 메일이 지연·제한될 수 있습니다.

## 3. 연결 값 두 개 확인하기

1. Firebase의 톱니바퀴에서 **프로젝트 설정(Project settings) → 일반(General)**을 엽니다.
2. **프로젝트 ID(Project ID)**를 확인합니다. 표시 이름과 다를 수 있습니다.
3. **내 앱(Your apps)**에 웹 앱이 없으면 웹 아이콘 **`</>`**을 누릅니다. 앱 닉네임을 `A1 FASHION`으로 입력하고 등록합니다. Firebase Hosting은 설정하지 않습니다. 현재 Cloudflare Pages를 계속 사용합니다.
4. 웹 앱의 **SDK 설정 및 구성(SDK setup and configuration)**에서 구성(Config) 보기를 선택하고 `apiKey` 값을 확인합니다.

필요한 값은 `projectId`와 `apiKey` 두 개뿐입니다. 이 코드는 서비스 계정의 비밀키·관리자 인증 JSON·Google 계정 비밀번호를 요구하지 않습니다. 전체 설정이나 인증키를 채팅·GitHub 파일에 붙이지 말고 다음 Cloudflare 설정에 직접 입력합니다. 웹 API 키는 Firebase 클라이언트용 식별 값으로, 서비스 계정 비밀키와는 다릅니다.

## 4. Cloudflare에 입력하기

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에서 **Workers 및 Pages → a1fashion**을 엽니다. 별도의 `a1` Worker가 있더라도 이번 설정 대상은 공개 주소를 제공하는 **Pages 프로젝트 `a1fashion`**입니다.
2. **설정(Settings) → 변수 및 시크릿(Variables and Secrets)**을 엽니다.
3. 환경을 **Production(프로덕션)**으로 선택하고 아래 두 값을 추가합니다.

| Cloudflare 변수 이름 | 입력할 값 |
| --- | --- |
| `FIREBASE_PROJECT_ID` | Firebase에서 확인한 정확한 `projectId` |
| `FIREBASE_WEB_API_KEY` | 같은 프로젝트의 웹 앱 `apiKey` |

4. 저장합니다. 가입 기능만 연결하는 데 D1 데이터베이스나 결제 서비스는 필요하지 않습니다.
5. **배포(Deployments)**로 돌아가 현재 운영 배포의 메뉴에서 **다시 배포/재시도(Retry deployment)**를 실행합니다. 설정 화면의 이름이 다르면 저장 후 새 운영 배포를 실행하는 항목을 사용합니다.
6. 배포 성공 뒤 [A1 FASHION](https://a1fashion.pages.dev)을 새로고침합니다. 변수를 저장한 것만으로 이미 실행 중인 배포가 갱신됐다고 가정하지 않습니다.

Preview(미리보기)에는 실제 회원 설정을 복사하지 않아도 됩니다. 시험 환경을 열려면 별도의 테스트 Firebase 프로젝트와 해당 도메인 설정을 사용하고 실제 고객 계정과 섞지 않습니다.

## 5. 실제 동작 확인하기

1. 사이트에서 회원가입을 열고 본인이 확인할 수 있는 이메일로 가입합니다. 필요한 가입·개인정보 안내를 읽고 동의합니다.
2. 받은 인증 이메일의 링크를 엽니다. 스팸함도 확인합니다.
3. A1으로 돌아와 이메일·비밀번호로 로그인합니다. 이메일 인증이 끝나기 전에는 로그인 세션을 발급하지 않습니다.
4. 로그인 상태와 로그아웃을 확인합니다. 로그인은 최대 약 한 시간이며, 만료 후 다시 로그인합니다.
5. 비밀번호 재설정을 요청해 실제 메일이 수신되고 새 비밀번호로 로그인되는지 확인합니다. 화면의 일반적인 발송 안내만으로 실제 수신까지 확인됐다고 판단하지 않습니다.
6. 시험용 계정의 회원탈퇴를 확인합니다. 가입·로그인을 해도 구독 결제 기록이 없으면 추천 기능은 계속 잠겨 있어야 합니다.

설정 누락이나 계정 생성·자격증명 확인 실패에서는 가입·로그인 성공으로 안내하지 않습니다. 계정 생성은 성공했지만 인증 메일 요청에 실패한 경우에는 그 상태를 구분해 안내하며, 같은 이메일로 가입을 반복하기보다 인증 메일을 다시 요청합니다. 이메일 인증을 마치기 전에는 로그인 세션을 발급하지 않습니다. 현재 개발 환경에서 수행하는 테스트와 위의 실제 운영 프로젝트·실제 이메일 테스트는 별개입니다. 이 문서를 작성하면서 소유자 계정이나 운영 회원을 생성하지 않았습니다.

## 개인정보와 로그인 상태

이메일·비밀번호는 HTTPS로 A1의 Cloudflare 서버 함수에 전달되고, 서버 함수가 Firebase에 중계합니다. A1은 비밀번호를 자체 데이터베이스에 저장하거나 로그로 기록하지 않습니다. 회원 인증 정보는 Firebase에서 관리합니다. 사진은 이 회원가입 요청에 포함되지 않으며 기존처럼 기기 안에서만 분석합니다.

로그인은 서명·발급자·대상 프로젝트·유효기간·이메일 인증 여부를 서버에서 검증한 후 `__Host-a1-session` 쿠키로 유지합니다. 쿠키는 `Secure`, `HttpOnly`로 설정하고 유효기간은 최대 한 시간입니다. 비밀번호나 로그인 토큰을 브라우저의 `localStorage`에 보관하지 않습니다. 사이트의 [개인정보 처리 안내](https://a1fashion.pages.dev/privacy.html)도 운영자가 확인합니다. 이 안내 문서는 법률 검토나 인증을 대신하지 않습니다.

추천 기능은 인증과 별도로 유료 구독 데이터베이스를 확인합니다. 회원가입·이메일 인증·로그인으로 유료 권한을 자동 생성하거나 결제하지 않습니다.

## 연결 오류 확인

소유자의 실제 가입 시도에서 기존의 포괄적인 ‘회원 서비스를 연결하는 중’ 오류가 보고되어 연결을 확인하고 있습니다. `/api/auth/config`는 Firebase 웹 SDK와 같은 공식 `GET /v1/projects` 요청으로 키 접근과 현재 사이트의 승인 도메인을 확인합니다. 이 확인에는 이메일·비밀번호가 필요하지 않고 계정 생성이나 메일 발송도 하지 않습니다. 설정값 앞뒤 공백은 정리하며, 값의 일부를 추측하거나 인증을 우회하지 않습니다.

연결이 실패하면 입력창을 열기 전에 안전한 안내 코드를 표시합니다. 공급자 응답 원문·키·비밀번호·회원 정보는 오류에 포함하지 않습니다.

| 안내 코드 | 확인할 사항 |
| --- | --- |
| `AUTH-CONFIG` | 운영 변수 두 개의 이름·값 형식·배포 적용 여부 |
| `AUTH-KEY` | 같은 Firebase 프로젝트의 웹 앱 API 키인지 |
| `AUTH-ACCESS` | API 키의 애플리케이션 제한 및 필요한 인증 API 접근 허용 범위 |
| `AUTH-METHOD` | Firebase 이메일/비밀번호 인증 사용 설정 |
| `AUTH-SIGNUP` | Firebase에서 일반 사용자의 새 계정 생성 허용 여부 |
| `AUTH-DOMAIN` | 현재 사이트가 해당 Firebase 프로젝트의 승인된 도메인 목록에 있는지 |
| `AUTH-API` / `AUTH-PROJECT` | 인증 서비스·프로젝트 설정 |
| `AUTH-CONNECT` / `AUTH-VERIFY` | 공급자 연결 및 서명 확인 서비스의 응답 |

안내 코드만으로 설정을 무작정 바꾸지 않고 해당 항목을 확인합니다. 모든 API를 무제한 허용하거나 유료 플랜으로 전환하는 절차는 포함하지 않습니다. 실제 운영 가입 성공은 오류 안내 개선과 별도로 확인해야 합니다.
