## 확인한 기능과 실제 수정

한국·미국·일본·영국·유럽 판매처 검색, 국가/배송지/통화, FREE/GENERAL/PREMIUM, 기존 스타일 추천·찜, 검증 상품 조회·동일 변형 비교, DEMO, 모의 프로모션, 채널별 동의·철회·삭제, Firebase 가입·로그인·탈퇴, 기기 내 무료 분석, 한국어·영어·모바일을 검토했습니다.

실제로 재현한 오류는 **마지막 권한 조회가 시작된 후 완료될 때까지의 사이에 구독이 만료되는 경우**였습니다. 이때 이전 시작 시각으로 승인된 결과가 200으로 나갈 수 있었습니다.

- 마지막 인증/DB 조회가 끝난 시각과 `accessUntil`을 다시 비교해 만료된 유료 결과를 403으로 차단합니다.
- 비동기 응답 도우미를 try/catch 안에서 await하여 거부 결과가 원시 예외/일반 500으로 빠지지 않고 기존 비공개 JSON 오류로 반환되도록 합니다.
- 계정 상태 조회 중 구독이 만료되면 GENERAL/PREMIUM 활성 상태 대신 FREE·비활성으로 표시합니다.
- 실제 RSA/SQLite와 제어된 시각으로 오류를 재현했습니다. 수정 전 200/활성 표시에 실패한 회귀 테스트가 수정 후 통과합니다.

문서의 실제 오류도 수정했습니다. 이미 사용 중인 Firebase 프로젝트가 없다는 오래된 문장, 회원 화면을 정적 출력에서 제외한다는 설명, 응답의 plan 필드 누락, 기존 D1에 빈 DB용 전체 스키마를 적용하도록 오해할 수 있는 안내를 바로잡았습니다. 승인 없는 재배포를 유도하지 않도록 Production/Preview 분리와 승인 절차를 명시했습니다.

## 미완성 운영 연결과 알려진 제한

현재 승인된 범위의 검증을 막는 재현 가능한 오류는 수정했습니다. 다음은 실제 운영 연결이 남은 부분입니다.

- 판매처 연결의 기본은 **검색 링크**, 가격 비교 기본은 **DEMO**입니다. 실제 상품 수집·eBay 운영 접근·Awin 광고주 피드 승인/매핑은 완료된 운영 기능으로 표시하지 않습니다.
- 승인된 기존 D1 상품을 읽는 경로는 준비되어 있지만, 실제 피드 수집·갱신과 공급자별 이용 조건·이미지·보관·가격 갱신 규칙은 별도입니다. 두 상품 승인 플래그는 기본 꺼짐으로 유지합니다.
- 실환율이 없으면 다른 통화의 구매 총액을 추정하지 않습니다. 목적지 근거가 없는 배송비·세금·관세도 0으로 계산하지 않습니다.
- 알림은 조건 평가·템플릿·중복 방지·모의 이력입니다. 실제 발송, 도메인/번호 소유 확인, 반송·차단·간편 수신 거부, 실제 비용 원장과 예약 전달은 별도 승인/연결 대상입니다.
- 구독 가격·결제 제공자·정기 청구·결제 웹훅·운영 권한 갱신은 미정/비활성입니다. 가입했다고 유료 권한을 주거나 시험용 결제 확인 행을 운영에 만들지 않습니다.

## 기존 회원에게 미치는 영향

같은 Firebase 프로젝트와 `(issuer, subject)` 식별자를 유지하므로 새 가입이나 비밀번호 변경을 요구하지 않습니다. 이번 작업은 회원 데이터를 읽거나 이전·삭제하지 않았습니다. 운영 D1이 준비되지 않아도 기존 무료 분석과 Firebase 인증은 별개로 유지되고 유료 기능은 잠깁니다.

기존 등급 없는 유효 유료 기록은 GENERAL 호환입니다. PREMIUM으로 자동 승격하지 않습니다. 첫 마이그레이션의 GENERAL 기본값 적용 정책은 기존 운영 기록을 분류·검토한 뒤 별도 승인해야 합니다. 과거 동의의 국가/언어/문안이 없으면 null로 보존하며 새 증빙으로 꾸미지 않습니다. 향후 적용 시에도 이 SQL에는 기존 회원 삭제·시험용 구독 부여·실제 청구가 포함되지 않습니다.

## GPT 스타일리스트의 다음 통합 단계

1. 글로벌 PR을 먼저 검토합니다. 승인 후 main 통합·배포 여부를 별도로 결정하며, 현재 AI 브랜치 `781b083`은 그대로 보존합니다.
2. 그 뒤 최신 main에서 새로운 AI 통합 브랜치를 만들고 **AI 전용 커밋 781b083만** 재적용하는 방식을 검토합니다. 기존 공개 AI 브랜치에 강제 rebase/push하지 않습니다.
3. 회원 탈퇴·개인정보/번역·화면 연결·테스트의 충돌을 해결할 때 이번 만료 처리·동의 감사·찜/철회 보호를 유지합니다. 이미 완성한 `catalog-repository.mjs`를 재사용하고 상품 검증을 중복 구현하지 않도록 조정합니다.
4. AI의 이전 `0003_ai_stylist_usage.sql`은 글로벌의 `0003_global_consent_context.sql`과 순서가 겹칩니다. 당시 최신 적용 이력을 보고 다음 번호(현재 기준 0004)로 조정하고 관련 테스트/문서를 맞춥니다. 이번에는 파일 변경·적용하지 않습니다.
5. 글로벌 전용 검사의 GPT 제외 조건은 그 별도 AI 단계에서 범위에 맞게 조정합니다. 회원·상품·동의·비용 제한 회귀와 기본 GPT 비활성 검증을 모두 다시 실행합니다.
6. 실제 GPT 키·모델/요금·예산·외부 처리 동의·운영 DB·실제 호출은 그 단계에서도 별도 승인 전 비활성화합니다.
