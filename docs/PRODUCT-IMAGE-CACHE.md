# 실제 상품 사진의 로컬 저장과 배포 범위 보호

2026-11-18, PR #4 `feature/product-fitting-lab`, 기준 `7b61547`.

## 수정한 실제 문제

기존 빌드는 `assets/catalog-images` 안의 파일 전체를 공개 패키지로 복사했다. 아직 실제 원본이 없는 폴더였지만, 앞으로 원본 사진을 넣을 때 상품 자료에 등록되지 않은 파일이나 개인 사진이 실수로 포함될 수 있는 경로였다.

이제 검증된 `local-copy` manifest에 등록된 파일만 공개한다. 등록되지 않은 파일은 읽거나 배포하지 않는다. 선택된 파일은 MIME/컨테이너 구조·치수·바이트 수·SHA-256·심볼릭 링크 여부를 확인하고 검증한 동일 바이트를 배포한다. manifest도 빌드에서 검증한 동일 바이트로 저장한다. 치수만 맞춘 비이미지·파일 교체·잘못된 해시·심볼릭 링크는 기존 정상 dist를 지우기 전에 거부한다.

## 오프라인 원본 저장

`scripts/cache-product-image.cjs`는 운영자가 갖고 있는 해당 상품 사진 파일을 기존 상품 ID에 연결하는 도구다. 네트워크 다운로드나 신규 권한 신청 도구가 아니다. 운영자가 이미 승인한 이미지 이용 범위를 재사용하고, 가격·재고·상품 설명·공급원 계약·승인 기한을 변경하지 않는다. 사용자 사진 분석 경로와 연결되어 있지 않으며 원본 개인 사진을 서버에 저장하지 않는다.

먼저 원본을 검사만 한다:

```sh
node scripts/cache-product-image.cjs --id musinsa-1168906 --file /workspace/product-originals/musinsa-1168906.jpg
```

확보한 실제 상품 파일을 로컬 복제에 반영한다:

```sh
node scripts/cache-product-image.cjs --id musinsa-1168906 --file /workspace/product-originals/musinsa-1168906.jpg --write
```

위 경로의 사진을 실제로 확보해 두어야 한다. 사용자의 체형 분석용 사진을 넣지 않는다. 명령은 해당 상품 이미지의 정확한 원본 바이트와 해시·헤더 치수를 기록하고 `assets/catalog-images/<상품ID>.<형식>`으로 저장한다. 다른 파일·미등록 목적지·진행 중인 저장 작업을 덮지 않으며, 반복 실행은 동일 내용이면 변경하지 않는다. manifest 반영 실패는 이전 정상 이미지를 복원하고 임시 파일을 정리한다. 파일명/개인 경로/입력 파일 내용은 CLI 오류 출력에 넣지 않는다.

PNG/JPEG/WebP, 6MB·30MP 범위를 지원한다. 애니메이션·알려진 GPS 메타데이터·뒤붙인 파일·위험한 경로는 거부한다. PNG의 압축/행 구조도 검사한다. JPEG/WebP는 전체 픽셀 코덱을 대체하지 않는 컨테이너 검사이며 실제 브라우저 디코딩은 별도로 확인한다. EXIF 방향은 원본에 보존하고 영수증에 기록한다. manifest의 width/height는 인코딩 헤더 치수이며 실제 화면 배치는 기존 브라우저 decode 치수를 사용한다.

입력 파일이 실제로 해당 상품의 사진인지는 자동 인식하지 않는다. 영수증의 `merchantDownloadVerified:false`, `visualProductMatchVerified:false`는 운영자 선택 파일에 대해 판매처 다운로드·내용 일치를 독립적으로 증명했다고 과장하지 않기 위한 구분이다. 테스트 도형이나 다른 의류 사진을 실제 상품 자료로 공개하지 않는다.

## 검증

- 전체 자동 검사 **376개 통과**. 추가된 파일/저장/패키징 검사 21개는 임시 폴더에서 실행한다.
- [브라우저 검증](validation/product-image-cache/private-fixture-browser.json): 기존 이미지 연결 8개에 실제 로컬 intake→동일 출처 이미지→개인 사진 별도 동의→2D·비교·삭제 1개를 추가해 **9개 통과**. 로컬 복제 경로의 외부 요청0·사진 재선택0·실제 canvas 픽셀 변화 확인.
- 브라우저 이미지는 명시적인 비공개 저장소 사진이다. 실제 판매처 의류의 원본 확보·착용 품질·iPad Safari를 검증했다는 증거가 아니다.
- 공개 빌드116파일/노출 검사117파일 통과. [이전 공개 패키지와 해시 비교](validation/product-image-cache/unchanged-public-artifacts.json) 결과 현재 공개 파일117개는 모두 동일하다. 기존 화면을 다시 개발하거나 변경하지 않았다.

## 실제 상품 원본 확보 상태

현재 공식 상품 후보10개, 이미지 참조9개, 실제 원본 로컬 복제0개다. 현재 Codex 환경의 강제 허용 목록에 `image.msscdn.net`, `img.29cm.co.kr`가 없어 원본 다운로드가 차단되어 있다. 같은 차단 요청을 반복하거나 우회하지 않았다. 이 두 호스트의 환경 설정이 적용되면 실제 원본을 확보해 이 경로로 저장하고 CDN/CORS 의존을 제거한 실제 상품 사진 피팅 검증을 진행할 수 있다.

사용 승인은 이미 반영했으며 새 승인 요청이 아니다. 이는 Codex 환경의 접속 설정이며 Cloudflare 운영 환경 변경이 아니다. 현재 제공된 도구에는 이 설정을 수정하는 기능이 없다.

모든 소비자 무료, Preview API503, 사진/체형값의 외부 전송 금지와 개인별 동의를 유지한다. main/Production/Firebase/DB/회원·구독 기록/결제/유료 AI를 변경하거나 활성화하지 않는다. PR #4는 Draft·미병합이다. 자연스러운 AI 착용 합성·개인 실사3D 복원·실제 의류3D 착용의 완성을 주장하지 않는다.
