# A1 FASHION — 목표 이미지 기반 실사형 3D 피팅 UI 구현 지시서

> 목표: 사용자에게 보여준 **짙은 네이비 배경/보라색 강조의 A1 FASHION 3D 가상 피팅 홍보 시안 이미지**를 실제 사용 가능한 반응형 웹 화면으로 최대한 가깝게 구현한다. **해당 이미지는 생성형 정적 디자인 시안**이지 작동하는 웹사이트나 복원 가능한 3D 모델 파일이 아니다. Codex 작업을 시작할 때 사용자가 그 시안 PNG를 이미지 첨부로 전달받아 반드시 함께 보도록 한다.

## 현재 프로젝트 — 반드시 재사용

- 작업 브랜치: `feature/product-fitting-lab` / Draft PR #4. Production 배포와 `main` 병합 금지.
- 이미 3D 실물 텍스처 모델 있음: `gltf-proof.html`, `assets/gltf-proof.js`, `assets/gltf-proof.css`, `assets/natural-avatar/sample.glb`, `assets/natural-avatar-profile.js`. 실제 라이선스/성능/사용 범위는 `docs/NATURAL-AVATAR.md` 참고. 처음부터 Three.js 렌더러/마네킹을 다시 만들지 말 것.
- 기존 체형분석·가상피팅 연구실: `avatar-lab.html`, `assets/avatar-lab.js`, `assets/avatar-photo-bridge.js`. 검색·무료 추천: `index.html`, `assets/shopping-search.js`, `stylist.html`, `assets/stylist.js`. 한영: `assets/i18n.js`.
- 기존 GLB는 stock 샘플 1종이며 사용자 사진에서 생성한 모델이 아니다. 원본 의복 1벌만 있음. 실제 의류 3D 모델, 개인화 전신 복원, 남녀 2종 맞춤 모델이 있다고 주장하지 말 것.
- 사진의 얼굴을 분석·전송하지 않는다. 실사 광고/시안 이미지를 '개인화된 아바타'처럼 오인시키지 않는다.

## 목표 이미지 레이아웃 (데스크톱 기준 1648x936, 실제 비율에 맞춘 반응형)

1. 상단/좌측: A1 FASHION 워드마크와 작은 영문 슬로건. 폭 약 250px의 세로 메뉴. 선택된 '가상 피팅'은 보라색 그라데이션 pill/card; 체형 분석, AI 스타일 추천(현재 규칙 기반 여부 정확히 표시), 쇼핑 검색, 스타일 저장. 왼쪽 하단 '내 체형 정보' 패널: 사용자 동의된 치수만 표시하고 편집 링크 제공. 데모 수치를 실제 측정치로 단정 금지.
2. 메인 배경: 차콜/네이비 #141824~#222638, 부드러운 그라데이션, 투명/블러 패널, 미세한 라이트 반사. 액센트 보라 #7B61E8 ~ #A58BFF. 타이포는 명료하고 접근성 대비 유지. 제목/버튼 한국어가 깨지지 않아야 함.
3. 좌측 메인 홍보 이미지 구간: 실사풍 남녀 전신/상반신 인물의 프리미엄 패션 컷이 보이는 영역. 단, 상업적 이용 권한 있는 이미지 또는 사용자 제작한 원본 자산만 사용. 저작권 미확인 외부 이미지 핫링크 금지. 이 사진은 UI 장식이며 WebGL 아바타가 아님을 구분.
4. 화면 중심: '3D 아바타', 360도 아이콘, 원형 조명 받침대, 실사 텍스처 전신 모델 캔버스. **실제** `sample.glb`를 기존 GLTFLoader로 렌더. 사용자 제스처로 회전/핀치 확대, 버튼으로 전면·측면·후면, 리셋/로딩/오류/재시도. 차분한 PBR 조명과 그림자, 모델 전신 프레이밍(발 잘림 금지). 현재 GLB의 얼굴/머리카락/옷 텍스처 유지.
5. 3D 캔버스 옆 세로 작은 프리뷰 3개: 전면/후면/측면. 클릭하면 실제 캔버스 카메라 이동. 한 모델의 각도임을 명확히.
6. 화면 오른쪽 패널: '의류 착용하기 | 코디 추천' 탭. 상의/하의/아우터/원피스/액세서리 카테고리 칩; 3열×3행 의류 카드(썸네일, 선택 강조, 이름). 실상품/실제 의상 교체 기능이 없으면 별도 **스타일 이미지 미리보기**로 표시하고 '선택한 의류 적용하기'가 의상을 입히는 척하지 않게 비활성/안내. 기존 3D 샘플이 실제로 착용 지원하는 옷만 버튼으로 적용. 완성된 피팅과 개별 상품 데이터를 조작해 표시 금지.
7. 화면 하단: 'AI 스타일 추천' 가로 스크롤 갤러리, 다양한 코디 카드와 찜 아이콘. 현재는 실제 추천 상품이 0개이므로 검증된 판매 상품인 것처럼 가격·재고·구매 링크를 만들지 말고 '스타일 영감 예시'로 구분. 국내 쇼핑 검색 결과로 연결할 때는 사용자의 의류 조건에 맞게 검색어 생성, 브라우저 제한 시 복사 대안 제공.
8. 남성/여성 토글: **실제 허가된 남녀 GLB가 둘 다 있을 때에만** 3D 모델 전환을 활성화. 그렇지 않으면 현재 제공 가능한 샘플 1종 표기와 추가 모델 준비 상태만 표시. 인물 사진 교체를 3D 모델 교체라고 속이지 말 것.

## 반응형/기능 완성 기준

- PC: 사이드바 230~260px / 중앙 3D 뷰 넓게 / 오른쪽 선택 패널 약 320px / 아래 추천 갤러리.
- iPad 가로: 좌측 메뉴 간소화, 3D 우선, 우측 의류 패널 한 화면에서 접근 가능. iPad 세로: 캔버스 위/카드 아래, 메뉴 축소. 모바일 390px: 상단 탭 + 3D 캔버스 + 하단 상품/스타일 리스트 순서. 가로 넘침과 겹치는 고정 요소 금지.
- 버튼은 모두 실제 동작하거나 지원하지 않는 이유가 명확해야 한다. 장식용 클릭 불가 버튼 만들지 말 것.
- WebGL 미지원/메모리 부족/자산 로드 실패에서 친절한 fallback을 제공하고 캔버스 GPU 자원을 정리.
- 기본 페이지 무료 공개 Preview에서 회원가입/결제/외부 AI 없이도 열려야 한다.
- 국제화 KO/EN 유지, 스크린리더 라벨, 키보드 포커스, 터치 영역, 이미지 대체텍스트, 개인정보 동의 및 삭제 유지.
- 기존 CSP, API 503 preview_isolated, 무료 정책, 유료 기능 비활성, Firebase/운영 DB/회원 데이터 보존.

## Codex 작업 순서 — 사용량 절감

1. 위 파일과 현재 코드 파일만 먼저 읽고 **중복개발 없이** `gltf-proof`를 실제 피팅 스튜디오 UI로 재배치한다. 필요하면 별도 `fitting-studio.html`을 추가하고 기존 페이지/링크는 보존한다.
2. 목표 이미지 첨부를 기준으로 CSS 레이아웃/색감/카드/타이포 구현. 실제 라이선스 이미지가 없으면 허용된 대체 자산을 쓰고 그 차이를 보고한다.
3. 3D 캔버스의 360도·전후측면·줌 버튼과 각도 프리뷰를 기존 GLB 뷰어에 연결한다.
4. 의류 패널은 실제 제공 가능한 모델·자산 범위에서만 동작하게 연결. '실제 제품 자동 피팅'은 준비되지 않았다면 **명확히 미구현** 표기.
5. 국내 쇼핑몰 맞춤 검색·무료 상담 버튼은 기존 `shopping-search.js` / `stylist.js`의 정상 경로로 연결.
6. 기존 `node scripts/build-site.cjs` 빌드와 새 화면 핵심 스모크테스트 후, 필요할 때만 전체 테스트 1회. 현재 여러 번 같은 검증 반복하지 말 것.
7. Playwright 캡처로 데스크톱 1440x900 / iPad 가로 1180x820 / 세로 820x1180 / 모바일 390x844를 시안 이미지와 비교. 실제 3D 렌더 프레임을 캡처하고 빈 캔버스/마네킹으로 대체하지 않는다.
8. 새 Preview URL, 사용된 저작물과 라이선스, 실사형 GLB 렌더링 결과, 각 버튼 동작, 지원 불가 영역, 변경 커밋을 보고. PR #4 Draft 유지.

## 출시/권한 경계

- `main` 병합·Production 배포, Cloudflare 로그인 재시도, 운영 Firebase/DB/회원/구독·결제 변경 금지.
- 유료 AI API, 무단 크롤링, 사진/신체 정보의 외부 전송, 무허가 의류 이미지·3D 모델 사용 금지.
- 사용자의 최종 목표는 **시안처럼 예쁘게만 보이는 이미지가 아니라, 3D 아바타를 돌려보고 실제 의류 검색 및 향후 피팅으로 이어지는 작동하는 A1 FASHION**이다.
